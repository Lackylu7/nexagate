# AI API 中转站起步手册

## 目标定位

第一版不要做“灰色 key 池”或“无限额度低价站”，而是做一个合规可运营的 AI Gateway：

- 海外用户主要购买 DeepSeek、Qwen、豆包、智谱、Kimi、硅基流动等高性价比模型的 OpenAI-compatible 接口。
- 国内用户主要使用国内可访问、已授权的模型渠道。
- OpenAI、Claude、Gemini、OpenRouter 等海外渠道只在上游条款、地区限制、付款主体和授权方式都允许时接入。
- 平台卖点是统一接口、余额计费、限流、失败重试、模型替换和稳定服务，不是绕限制。

## 为什么这样做

真正有利润空间的是“模型成本差 + 稳定运营能力”：

- 海外开发者愿意为更便宜的推理成本、兼容 OpenAI 的接口和可用文档付费。
- 国内模型在文本、代码、翻译、摘要、客服等场景已经足够可用，适合面向海外做低成本批量处理。
- 单纯倒卖 OpenAI/Claude 风险高，容易遇到封号、支付冻结、滥用投诉和条款问题。

## 第一版产品范围

先只做这些：

- OpenAI-compatible `/v1/chat/completions`
- `/v1/models`
- 用户注册、登录、API token
- 预付费余额和按量扣费
- 模型分组：`global-low-cost`、`china-mainland`、`premium-authorized`
- 单用户限速、单 token 限额、异常用量封禁
- 英文首页、英文文档、中文后台
- Stripe 或其他合规支付方式，先用预付费

第一版暂时不要做：

- 无限套餐
- 绕地区限制的海外模型转发
- 共享用户 key 池
- 免费大额度试用
- 面向国内宣传“访问 OpenAI/Claude”
- 代充值、代绑卡、账号租赁

## 推荐模型分组

### `global-low-cost`

面向海外用户，主推性价比：

- DeepSeek
- Qwen
- Doubao / Volcengine
- Zhipu
- Moonshot / Kimi
- SiliconFlow

适合文案、翻译、摘要、客服、轻代码、批处理任务。

### `china-mainland`

面向国内用户，使用国内可访问渠道：

- DeepSeek
- Qwen
- Doubao / Volcengine
- Zhipu
- Baidu
- Tencent
- Xunfei

不要把这个分组包装成“国内访问境外受限模型”。

### `premium-authorized`

只接合法授权、条款允许的海外渠道：

- OpenAI
- Claude
- Gemini
- OpenRouter
- Together
- Groq

这个分组建议价格更高、默认不开通，由管理员审核后分配。

## 部署建议

第一台机器建议放在香港、新加坡或日本：

- 兼顾国内和海外访问延迟。
- 访问国内外上游 API 更灵活。
- 支付、域名、CDN、监控选择更多。

基础配置：

- 2 核 4G 起步，后续按并发扩。
- PostgreSQL + Redis。
- Nginx 或 Caddy 负责 HTTPS 和反向代理。
- 数据库、Redis、后台密码全部换成强随机值。
- 开启日志，但不要长期保存完整 prompt，除非业务和合规确实需要。

可以从根目录的 `docker-compose.gateway.example.yml` 复制出生产配置。

## 上线配置清单

1. 准备域名，例如 `nexagate.yourdomain.com`。
2. 部署 `docker-compose.gateway.example.yml`。
3. 配置 HTTPS。
4. 登录后台，创建管理员账号。
5. 添加 1 个低成本模型渠道，先用 DeepSeek 或 SiliconFlow。
6. 建立 `global-low-cost` 分组。
7. 创建测试用户，发放少量余额。
8. 用 curl 测试 OpenAI-compatible 接口。
9. 开启注册限制、邮箱验证、用量限额。
10. 接入支付前，先用兑换码或人工充值跑通 10 个真实用户。

## 定价建议

第一版不要追求复杂定价，先用简单倍率：

- 低成本模型：成本价上浮 30% 到 80%。
- 高级授权模型：成本价上浮 20% 到 50%。
- 免费额度只给很小额度，且绑定邮箱、IP、设备风控。
- 大客户走人工开通，单独设置额度和速率。

更重要的是防亏：

- 所有用户预付费。
- 单次请求最大 token 限制。
- 单 token 每分钟请求限制。
- 余额不足立即拒绝。
- 上游报错不重复无限重试。

## 风控底线

必须做：

- 不保存或少保存用户 prompt。
- 明确隐私政策，说明请求会转发到哪些上游模型服务。
- 禁止滥用：垃圾邮件、诈骗、恶意代码、凭证窃取、绕过安全限制。
- 异常用量自动暂停。
- 不承诺“永久免费”“无限量”“保证可访问受限模型”。
- 每个上游渠道都确认服务条款是否允许转售、代理、白标或公开服务。

## 下一步二开方向

优先级从高到低：

1. 英文落地页和开发者文档。
2. 默认模型套餐和分组模板。
3. 注册风控、邮箱验证、IP 限流。
4. 支付接入和自动充值。
5. 用量看板和成本利润看板。
6. 模型自动 fallback。
7. 面向跨境电商、SEO、客服场景的预设 API。

先跑通“10 个真实海外开发者付费调用”，再考虑大规模改 UI 或重构架构。
